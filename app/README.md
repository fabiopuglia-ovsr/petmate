# Petmate — Flutter app (iOS + Android)

Implements `../docs/INTERFACES.md` (v0.2) §4 WebRTC/DataChannel `ctl`, §6 REST + signaling, §7 BLE
provisioning, following the decisions in `../docs/MVP.md`.

**MVP mode is the default** (`--dart-define=PETMATE_MVP=true`): Login → *I miei robot* → BLE wizard →
Live video. Every other screen (feeding, schedules, joystick, activity, settings, push) is still in the
code but not routable. Build the full app with `--dart-define=PETMATE_MVP=false`.

| dart-define | Default | Meaning |
|---|---|---|
| `PETMATE_API` | `http://192.168.1.50:8000/v1` | Default cloud REST base. Editable at runtime on the login screen (*Impostazioni avanzate → Server*), persisted in secure storage, validated with `GET {base}/health`. Signaling URL is derived (`http→ws`, `https→wss`, `<base>/signal`). The wizard sends this same base to the robot as `cloud_url`. |
| `PETMATE_MVP` | `true` | MVP navigation and offer (video `recvonly` + DataChannel `ctl`, no mic/camera). |
| `PETMATE_FCM` | `false` | Push notifications (full app only; needs Firebase config files). |

## Requirements

- **Flutter ≥ 3.35** (Dart ≥ 3.9) — required by `go_router 17.2.3`. Checked against the 3.35…3.44 API
  surface (see `REVIEW_NOTES.md`). `flutter --version` first.
- Android: JDK 17, Android SDK 36 (Flutter ≥ 3.35 already defaults to `compileSdk 36`, `minSdk 24`,
  which satisfies flutter_webrtc 1.5.2 / flutter_secure_storage 10 / flutter_blue_plus).
- iOS: Xcode 16+, CocoaPods, iOS **13.0** minimum, a real device (no BLE/camera in the simulator).
- The cloud running on your PC: `uvicorn app.main:app --host 0.0.0.0 --port 8000` (bind to `0.0.0.0`,
  **not** 127.0.0.1, or the phone and the robot cannot reach it). Find the PC LAN IP with
  `ipconfig` / `ip addr` / `ipconfig getifaddr en0`.

## First run — Android

1. On the phone: *Settings → About → tap "Build number" 7×*, then *Developer options → USB debugging* on.
   Connect via USB, accept the RSA prompt. `flutter devices` must list it.
2. Generate the platform scaffolding **without touching lib/** (existing files are never overwritten):

   ```bash
   cd app
   flutter create . --org com.oversonic --project-name petmate --platforms android,ios
   git status   # lib/, test/, pubspec.yaml, AndroidManifest.xml must be unchanged
   ```

   `flutter create` skips files that already exist, so our `AndroidManifest.xml`,
   `res/xml/network_security_config.xml` and `test/widget_test.dart` are kept.
3. Check `android/app/build.gradle.kts` (generated): `compileSdk = flutter.compileSdkVersion` and
   `minSdk = flutter.minSdkVersion` are fine on Flutter ≥ 3.35. On an older/custom template set:

   ```kotlin
   android {
       compileSdk = 36            // flutter_webrtc 1.5.2 / flutter_secure_storage 10 compile against 36
       defaultConfig { minSdk = 24 }
   }
   ```
4. Dependencies, tests, run:

   ```bash
   flutter pub get
   flutter test
   flutter run --dart-define=PETMATE_API=http://<ip-pc>:8000/v1
   ```

   Commit the generated `pubspec.lock` once it works.

## First run — iOS

1. Scaffolding + iOS settings. The Info.plist is **generated by `flutter create`** (its format changed
   in Flutter 3.38: UIScene lifecycle) and then patched by a script that adds our keys
   (`NSAppTransportSecurity` with `NSAllowsLocalNetworking` + `NSAllowsArbitraryLoads` (dev only),
   `NSBluetoothAlwaysUsageDescription`, `NSCameraUsageDescription`, `NSMicrophoneUsageDescription`,
   `NSLocalNetworkUsageDescription`) and fixes the Podfile (`platform :ios, '13.0'`,
   permission_handler macros `PERMISSION_BLUETOOTH/MICROPHONE/CAMERA/NOTIFICATIONS=1`):

   ```bash
   cd app
   flutter create . --org com.oversonic --project-name petmate --platforms android,ios
   flutter pub get
   flutter build ios --config-only --no-codesign   # creates ios/Podfile
   python3 tools/patch_ios.py               # idempotent, re-run after any flutter create
   cd ios && pod install && cd ..
   ```
2. Signing: `open ios/Runner.xcworkspace` → *Runner* target → *Signing & Capabilities* → select your
   Team, keep *Automatically manage signing*, make the bundle id unique if needed
   (`com.oversonic.petmate.<yourname>`). On the phone: *Settings → Privacy & Security → Developer Mode*
   on (iOS 16+), and trust the developer certificate under *General → VPN & Device Management* after the
   first install.
3. `flutter run --dart-define=PETMATE_API=http://<ip-pc>:8000/v1`. Accept the **Local Network** prompt
   (otherwise every LAN request fails silently) and the Bluetooth prompt when the wizard starts.

flutter_webrtc 1.5.2 on iOS: deployment target 13.0, WebRTC-SDK pod (~ 50 MB download on the first
`pod install`), no extra Podfile changes. Camera/mic descriptions are required by Apple because the
binary links capture code, even though the MVP never requests them.

## Using the MVP

1. Login screen → *Impostazioni avanzate* → *Server* `http://<ip-pc>:8000/v1` → *Verifica* (must say
   "Server raggiungibile") → register/login.
2. *I miei robot* → *Aggiungi robot* → the wizard asks for Bluetooth ("Dispositivi nelle vicinanze" on
   Android 12+; location on Android ≤ 11), turns Bluetooth on, scans for `Petmate-XXXX`, connects
   (MTU 247 on Android), reads `device_info` + `wifi_scan`, you pick the SSID (or type a hidden one),
   the app gets a fresh claim token, encrypts, writes ≤ 180 B chunks and follows the status
   notifications. On `done` it polls `GET /devices` (+ presence) for up to 60 s, then opens Live.
3. Live: video full screen, status chip, *Riconnetti*, optional snapshot (DataChannel `snapshot`).
   No microphone/camera permission is requested.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| *Verifica*: "Server non raggiungibile" | Cloud bound to 127.0.0.1 (use `--host 0.0.0.0`); PC firewall blocks TCP 8000 (Windows: allow Python on *private* networks; macOS: allow incoming for python); phone on mobile data or guest Wi-Fi (client isolation). Test from the phone browser: `http://<ip-pc>:8000/v1/health` → `{"ok":true}`. |
| Android: `CLEARTEXT communication not permitted` / iOS: ATS error | Platform files not applied: Android manifest must have `usesCleartextTraffic="true"` + `networkSecurityConfig`; iOS: run `python3 tools/patch_ios.py`, then rebuild (a hot restart is not enough). |
| iOS: requests time out only on iPhone | Local Network permission denied: *Settings → Petmate → Local Network* on. |
| Wizard finds no robot | pm-core not in provisioning mode (not provisioned yet, or hold the paw button 5 s — 10 min window); `systemctl status petmate-core` / `bluetoothctl show` on the Pi; phone too far; Android ≤ 11 needs **location services on** (the app says so); Android 12+: permission "Dispositivi nelle vicinanze" denied → *Apri impostazioni*. Some phones cache GATT: toggle Bluetooth off/on. |
| Connects but "Il robot non risponde come previsto" | Service/characteristic UUIDs not found: pm-core GATT server not running or an old build; restart `petmate-core`. |
| "Password Wi-Fi errata" / "non trova questa rete" | Check case-sensitive SSID/password. The Pi 5 supports **both 2.4 GHz and 5 GHz**; on 5 GHz DFS channels (52–144) the first association can take longer, and the Wi-Fi regulatory country must be set on the Pi (`raspi-config` → *Localisation → WLAN Country*) or 5 GHz stays disabled. Hidden SSIDs: use *Altra rete…*. |
| "connesso al Wi-Fi ma non raggiunge il server" / online timeout after 60 s | The robot uses the same `cloud_url` as the app: never `localhost`; robot and PC must be on the same LAN (no AP isolation); firewall port 8000; on the Pi `journalctl -u petmate-core -f`. |
| Live: "non ha risposto entro 15 secondi" | Robot online but pm-core WebRTC not answering (check its log); or the robot is still registering — wait for the green dot and retry. |
| Live: "Connessione video non riuscita" (ICE failed) | Phone and robot on different networks without TURN; in the MVP keep both on the same LAN. |
| `flutter pub get` version solving failed | Flutter older than 3.35 → upgrade (`flutter upgrade`). Do not pin `intl`: it must stay `any` (Flutter pins it). |
| iOS `pod install` errors | `pod repo update`; delete `ios/Pods ios/Podfile.lock` and retry; check `platform :ios, '13.0'`. |

## Structure

```
lib/
  main.dart, app_router.dart          provider + go_router (auth redirect, MVP route set)
  l10n/strings.dart                   all UI strings (IT), pure Dart
  core/
    env.dart                          dart-defines + pure URL helpers (normalize, health, ws derivation)
    config/server_config.dart         runtime server URL (secure storage, GET /health)
    api/api_client.dart               REST §6 (mutable base URL)
    auth/                             JWT in flutter_secure_storage, AuthState
    signaling/signaling_client.dart   WS §6: hello, 20 s ping/pong, backoff reconnect, presence, 4401 → sign-out
    webrtc/offer_plan.dart            pure: transceiver plan (MVP: video recvonly + DC ctl), SDP summary
    webrtc/live_session.dart          non-trickle offer (≤ 3 s gathering), 15 s answer timeout, error mapping
    webrtc/session_hub.dart           one live session; DC routing / REST fallback (full app)
    provisioning/prov_crypto.dart     X25519 + HKDF-SHA256 + ChaCha20-Poly1305, ≤ 180 B chunks (pure Dart)
    provisioning/prov_errors.dart     device/app error codes → Italian message + retry action
    ble/                              §7 UUIDs, permissions, adapter, scan/connect/MTU/read/write/notify
  features/ auth, devices, onboarding, live (+ full app: device_home, schedule, settings, activity)
test/   env_test, offer_plan_test, error_mapping_test, prov_crypto_test (Python vector), models_test,
        teleop_test, widget_test
tools/  prov_vector.py (+ .json) — reference vector; patch_ios.py — iOS Info.plist/Podfile patcher
```

## Crypto interop

`python3 tools/prov_vector.py --write tools/prov_vector.json` regenerates the vector (fixed keys and nonce,
pm-core-side decryption verified in the same script). `test/prov_crypto_test.dart` checks byte-for-byte that
the Dart implementation produces the same public key, shared secret, HKDF key, ciphertext+tag, JSON message
and BLE writes.
